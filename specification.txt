1. Introduction
1.1 Purpose
This Software Requirements Specification (SRS) defines the functional and non-functional requirements for RevCat, a commercial software application for version control and comparison of Programmable Logic Controller (PLC) project files.
1.2 Scope
RevCat provides engineers with the ability to:

Import and parse PLC project exports from supported platforms
Compare any two versions of a project or routine
Visualise differences graphically for Ladder Logic, Function Block Diagram, and Structured Text
Generate professional PDF reports of comparisons
Process large batches of comparisons via command line interface

3.2 Use Cases
UC-01: Compare Two Project Versions (GUI)
Actor: Any user
Precondition: User has two XML export files from the same PLC platform
Trigger: User launches RevCat and selects comparison mode
Main Flow:

User selects "New Comparison" from main menu
User selects source file (Version A / baseline)
User selects target file (Version B / modified)
System validates both files are compatible (same platform, parseable)
System parses both files and builds internal representation
System performs diff analysis
System displays summary of changes (counts by category)
User navigates to specific changes of interest
System displays graphical diff for selected item

Alternative Flows:

4a. Files incompatible: System displays error with reason
5a. Parse error: System displays error with location in file

Postcondition: User can view all differences between the two versions
UC-02: Export Comparison to PDF (GUI)
Actor: Any user
Precondition: Comparison has been performed (UC-01 complete)
Trigger: User selects "Export to PDF"
Main Flow:

User selects "Export to PDF" from menu or toolbar
System displays export options dialog
User configures export options (scope, detail level, metadata)
User selects output location
System generates PDF report
System displays success message with file location
(Optional) System opens PDF in default viewer

Postcondition: PDF report saved to specified location
UC-03: Batch Comparison (CLI)
Actor: Power user / automated system
Precondition: User has prepared batch input file or directory structure
Trigger: User executes RevCat from command line with batch parameters
Main Flow:

User executes: revcat batch --input manifest.json --output ./reports/
System reads batch manifest file
System validates all input files exist and are accessible
For each comparison in manifest:
a. System parses source and target files
b. System performs diff analysis
c. System generates PDF report
d. System logs result (success/failure)
System generates batch summary report
System exits with appropriate return code

Alternative Flows:

3a. Missing files: System logs error, continues with remaining comparisons
4a. Parse error: System logs error for that comparison, continues

Postcondition: PDF reports generated for all valid comparisons, batch summary available
UC-04: Single Comparison (CLI)
Actor: Power user / automated system
Precondition: User has two XML export files
Trigger: User executes RevCat from command line
Main Flow:

User executes: revcat compare --source v1.L5X --target v2.L5X --output report.pdf
System parses source and target files
System performs diff analysis
System generates PDF report
System exits with return code 0

Postcondition: PDF report generated

4. Functional Requirements
4.1 File Import and Parsing
FR-010: L5X File Import
Priority: Must Have
Description: System shall import and parse Rockwell L5X XML export files.
Acceptance Criteria:

System accepts L5X files from Studio 5000 v20 through v36
System extracts all Programs, Routines, and Tasks
System extracts all Tags (controller-scope and program-scope)
System extracts all Add-On Instructions
System extracts all routine content (LD, FBD, ST)
System handles files up to 500MB in size
System reports parse errors with line number and description

FR-011: XEF File Import
Priority: Must Have
Description: System shall import and parse Schneider XEF XML export files.
Acceptance Criteria:

System accepts XEF files from Unity Pro v11+ and Control Expert v14+
System extracts all Program Units and Sections
System extracts all Variables (elementary and derived)
System extracts all Derived Function Blocks (DFBs)
System extracts all section content (LD, FBD, ST)
System handles files up to 500MB in size
System reports parse errors with line number and description

FR-012: File Validation
Priority: Must Have
Description: System shall validate input files before processing.
Acceptance Criteria:

System verifies file is well-formed XML
System identifies platform type (Rockwell/Schneider) from file content
System verifies both files in a comparison are same platform type
System provides meaningful error messages for validation failures

4.2 Diff Analysis
FR-020: Program Structure Diff
Priority: Must Have
Description: System shall identify structural changes in program organisation.
Acceptance Criteria:

System identifies added programs/units
System identifies removed programs/units
System identifies renamed programs/units (where detectable)
System identifies added/removed routines/sections
System identifies added/removed tasks (Rockwell)

FR-021: Routine Content Diff - Ladder
Priority: Must Have
Description: System shall perform rung-level diff analysis on Ladder routines.
Acceptance Criteria:

System identifies added rungs with position
System identifies removed rungs with original position
System identifies modified rungs
System identifies moved rungs (position change only)
System identifies rung comment changes
For modified rungs, system identifies changed elements:

Instructions (added/removed/changed)
Operands (tag references changed)
Branch structure changes



FR-022: Routine Content Diff - FBD
Priority: Must Have
Description: System shall perform network-level diff analysis on FBD routines.
Acceptance Criteria:

System identifies added networks with position
System identifies removed networks with original position
System identifies modified networks
For modified networks, system identifies:

Added/removed function blocks
Changed block parameters
Changed connections between blocks
Changed block positions (layout changes)



FR-023: Routine Content Diff - Structured Text
Priority: Must Have
Description: System shall perform line-level diff analysis on ST routines with token highlighting.
Acceptance Criteria:

System identifies added lines with position
System identifies removed lines with original position
System identifies modified lines
For modified lines, system identifies changed tokens:

Variable names
Operators
Literal values
Function/FB calls
Comments


System handles ST syntax variations between platforms

FR-024: Tag Database Diff
Priority: Must Have
Description: System shall identify all changes to tag/variable definitions.
Acceptance Criteria:

System identifies added tags
System identifies removed tags
System identifies modified tags with specific changes:

Data type changes
Description changes
Initial value changes
Scope changes
Array dimension changes


System handles platform-specific tag attributes

FR-025: Comments and Documentation Diff
Priority: Must Have
Description: System shall track changes to comments and documentation strings.
Acceptance Criteria:

System tracks rung/network comments
System tracks routine descriptions
System tracks program descriptions
System tracks tag descriptions
System indicates comment-only changes distinctly from logic changes

5.4 Key Design Patterns
5.4.1 Parser Plugin Architecture
Parsers implement a common interface to allow easy addition of new platforms:
pythonfrom abc import ABC, abstractmethod
from models.project import Project

class BaseParser(ABC):
    @abstractmethod
    def can_parse(self, filepath: Path) -> bool:
        """Return True if this parser can handle the file."""
        pass
    
    @abstractmethod
    def parse(self, filepath: Path) -> Project:
        """Parse file and return unified Project model."""
        pass
    
    @abstractmethod
    def get_platform_name(self) -> str:
        """Return human-readable platform name."""
        pass

    """Syntax token."""

8. Command Line Interface
8.1 Command Structure
revcat [OPTIONS] COMMAND [ARGS]

Options:
  --version       Show version and exit
  --verbose, -v   Enable verbose output
  --quiet, -q     Suppress non-error output
  --help          Show this message and exit

Commands:
  compare   Compare two PLC project files
  batch     Process multiple comparisons from manifest
  info      Display information about a project file
  gui       Launch graphical interface (default if no command)
8.2 Compare Command
revcat compare [OPTIONS] --source FILE --target FILE

Compare two PLC project export files.

Options:
  --source, -s FILE       Source/baseline file (required)
  --target, -t FILE       Target/modified file (required)
  --output, -o FILE       Output PDF file (default: comparison_TIMESTAMP.pdf)
  --format FORMAT         Output format: pdf, json, html (default: pdf)
  --include-unchanged     Include unchanged items in output
  --detail-level LEVEL    Detail level: summary, standard, full (default: standard)
  --header TEXT           Custom header text for PDF
  --footer TEXT           Custom footer text for PDF
  --logo FILE             Company logo for PDF cover
  --help                  Show this message and exit

Examples:
  revcat compare -s baseline.L5X -t modified.L5X -o changes.pdf
  revcat compare -s v1.XEF -t v2.XEF --detail-level full
8.3 Batch Command
revcat batch [OPTIONS] --input MANIFEST --output DIRECTORY

Process multiple comparisons defined in a manifest file.

Options:
  --input, -i FILE        Manifest file (JSON or YAML) (required)
  --output, -o DIR        Output directory for reports (required)
  --workers, -w INT       Parallel workers (default: 4)
  --continue-on-error     Continue processing if individual comparisons fail
  --summary-only          Generate only batch summary, no individual PDFs
  --help                  Show this message and exit

Examples:
  revcat batch -i comparisons.json -o ./reports/
  revcat batch -i manifest.yaml -o ./output/ -w 8 --continue-on-error
